# Практикум: потоки и гонка

Тема 4, модуль 1. Два потока по 1 000 000 раз увеличивают общий счётчик.

## Сборка и запуск

```sh
cc -Wall -Wextra -O0 -pthread race.c  -o race
cc -Wall -Wextra -O0 -pthread fixed.c -o fixed
for i in 1 2 3 4 5; do ./race; done
./fixed
```


Результат одинаков при каждом запуске.

## Почему гонка не воспроизводится стабильно

`counter++` — это три шага: прочитать значение, прибавить единицу, записать
обратно. Обновление теряется, только если второй поток вклинился между чтением
и записью первого: оба прочитали одно значение и записали одно и то же, из двух
прибавлений осталось одно.

Произойдёт ли такое наложение, программа не определяет:

- **Планировщик.** Он решает, когда прервать поток и на каком ядре его
  запустить; это зависит от загрузки системы в данный момент.
- **Число ядер.** На нескольких ядрах потоки работают одновременно и
  сталкиваются часто; на одном ядре потеря возможна только при переключении
  ровно между чтением и записью.
- **Время старта потоков.** Если первый поток закончил цикл до запуска второго,
  наложений нет и ответ случайно верный.
- **Оптимизация.** С `-O2` компилятор может свернуть цикл в одно сложение, и
  окно для гонки почти исчезает.

Поэтому число потерь каждый раз разное, а иногда ответ получается правильным.
Верный результат не доказывает отсутствие ошибки: гонка данных в C —
неопределённое поведение.

Мьютекс делает инкремент критической секцией: три шага выполняет только один
поток за раз, вклиниться некуда, поэтому потерь нет при любом расписании.

Проверка инструментом, а не повторными запусками:

```sh
cc -fsanitize=thread -g -O1 race.c -o race_tsan && ./race_tsan
```

ThreadSanitizer сообщает `data race` на `counter` для `race.c` и не выдаёт
предупреждений для `fixed.c`.
